# 病害症状分流

复现输入：作物为番茄；叶片边缘暗绿色水渍状大病斑，高湿时叶背出现白色霉层，果实褐色硬斑且不软腐，茎秆变褐缢缩。

修复前：进入仅支持缺素的检索流程，返回 `NO_MATCH`，追问“发黄是从新叶还是老叶开始的？”。根因是病害症状缺少独立分流。

修复后：在营养元素评分前检查有来源的症状组合，返回 `decision: DISEASE_SUSPECTED` 和 `triage`，包含疑似病害、匹配特征、核实问题、观察建议和来源。此例提示优先排查番茄晚疫病，不输出缺素结论、施肥方案或农药用量。普通缺素仍走原流程。

`data/kb/disease_triage.json` 收录五组初始规则：番茄晚疫病、早疫病、灰霉病，水稻稻瘟病，黄瓜霜霉病。它们是人工核对的症状组合，不是训练数据集，也不代表全面的病害识别能力。必须同时满足多个特征，并匹配作物；否定描述不能直接触发对应特征。新增规则需核对政府或科研机构原文，保留直接来源链接，并补充阳性、否定及作物不匹配测试。修改后重启服务加载。

前后端需配套发布：前端必须认识新 decision 并展示 triage。后端内置的旧静态网页需另行使用新版前端构建替换；本次联调使用独立前端开发服务。聊天接口也会展示分流提示。未配置规则文件时保留原缺素流程。

验证：29 项 Java 测试通过；配套前端 31 项测试、类型检查与构建通过。真实服务和网页以用户原文验证病害卡片及来源链接，无施肥建议、无模拟响应；390px 屏幕无横向溢出。
