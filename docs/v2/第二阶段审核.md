# V2 第二阶段：本体查询服务（待审核）

## 本次完成

后端引入 Apache Jena ARQ 5.3.0，直接读取第一阶段的标准 TTL 文件，以外置 SPARQL 文件执行两类只读查询。每次调用创建独立模型并关闭资源，修改 TTL 或查询文件后，下次查询即可读取新内容。

- `GET /api/v1/ontology/query/candidates?id=OldLeafUniformChlorosis`：返回缺氮候选及氮元素 URI。
- `GET /api/v1/ontology/query/remedies?id=NitrogenDeficiency`：返回检测复核与农技指导方向，不虚构用量。
- 响应包含 `status`、`scope`、实际执行的 `sparql` 和 `rows`；沿用统一 ApiResponse 包装。
- 未知实体返回 `NOT_COVERED` 和空结果；非法标识或未知查询类型返回 HTTP 400。
- 外置查询只允许两种预定义模板，实体标识校验并以参数化 IRI 绑定，客户端不能执行任意 SPARQL。

## 如何运行与核对

在 backend 目录运行 Maven 测试或 Spring Boot。默认资产目录为 `../data/ontology`；可通过 `--agent.ontology.dir=绝对路径` 覆盖。

示例：`http://127.0.0.1:18080/api/v1/ontology/query/candidates?id=OldLeafUniformChlorosis`。

现有运行的旧 JAR 不包含新接口，需重新构建再启动。本次没有替换你正在运行的服务。

## 边界

这是本体查询，不是规则推理。当前关系为通用知识，尚无经审核的作物适用断言，因此结果不能视作某种作物的确诊或施肥依据。接口明确返回范围提示，不计算虚假的置信度。
