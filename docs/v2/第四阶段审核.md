# V2 第四阶段：五步问答与页面接入（待审核）

新增 `POST /api/v1/ontology/question`，请求示例：

```json
{"crop":"水稻","question":"分蘖期，老叶先均匀黄化，植株长势偏弱。"}
```

## 真实处理链路

1. 规则模板解析作物、部位、形态、生育期和首次发生描述。明确匹配不了、否定或混合部位不清时要求补充；不调用大模型猜测。
2. 将本次观察写入请求独立模型，从外置 SPARQL 按观察部位读取候选。这一步先于规则执行，不再无差别列出所有缺素。
3. Jena 运行外置规则，返回支持、排除、优先复核与冲突。冲突时暂停判断。
4. 复用 EvidenceSearchService，从已有知识库检索证据；只保留与受支持元素一致的、原服务按作物适用范围筛选的内容。无证据或服务故障明确标记，不补写细节。
5. 确定性模板组织输出，只复述候选与范围提示；原始证据单列。mode=TEMPLATE，不冒充模型生成。

返回统一 ApiResponse。data 中提供 slots、stages、reasoning、evidence、answer、mode；五步各有实际完成/跳过/空结果/不可用状态。前端仓库分支 `feat/ontology-workbench` 新增“本体推理”页读取这些真实字段。

## 测试与人工验收

后端 78 项测试通过；前端 66 项测试及构建通过。实际浏览器覆盖正常、冲突、未知作物、模糊描述和手机无横向溢出。后端测试进一步覆盖证据故障、排除元素证据过滤及错误作物、否定、绿色叶脉但无失绿等解析边界。

前端地址 `http://127.0.0.1:5173/#/ontology`，有正常和冲突输入示例，但结果全部由后端计算，不是预设答案。

## 尚未完成

- 本轮完成的是问答链路及推理过程展示；“本体构建过程”动态树、逐条人工审核与增量回放尚未开发。
