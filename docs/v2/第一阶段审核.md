## 请审核的建模决策

| 决策 | 当前方案 | 理由与待确认项 |
| --- | --- | --- |
| 顶层概念 | Crop、PlantPart、Symptom、Nutrient、DeficiencyDisorder，加 ManagementMeasure | 措施单独建类，便于后续查询；目前不提供具体用量 |
| 元素分组 | 氮、钾、镁进入 MacroNutrient，铁进入 MicroNutrient | 遵循赛题示例；镁在常用农学分类中属于中量元素，因此中文标签明确“含中量元素，按赛题分组”，请确认是否另设 SecondaryNutrient |
| 移动性 | MobileMacroNutrient 为 MacroNutrient 子类 | 当前只表达氮、钾、镁的移动性分组；不把全部大量元素认定可移动 |
| 症状层级 | Symptom 下设变色、坏死 | 老叶均匀黄化、老叶脉间失绿、新叶脉间失绿、叶缘坏死分别建为实例 |
| 部位 | PlantPart → Leaf，老叶、新叶为 Leaf 实例；叶缘为 PlantPart 实例 | 后续可加入叶龄属性，目前采用赛题最小模型 |
| 互斥 | MacroNutrient 与 MicroNutrient 互斥 | 约束分类，不把老叶和新叶同时出现直接当作逻辑矛盾；“首先发生”需要后续观察事件建模 |
| 作物适用范围 | 收录水稻、玉米、番茄，但暂不写 affectsCrop 断言 | 不能仅凭通用缺素症状虚构每种作物的适用证据，审核具体来源后再加入 |
| 措施 | 仅保留检测复核与农技指导方向 | 不凭空填写肥料用量、生育期等知识 |

## 已交付

- `data/ontology/ohcp-ontology.ttl`：标准命名空间、英文实体名、中文标签、6 条对象属性及 domain/range、类层级和互斥声明。
- `data/ontology/hierarchy.mmd`：由本阶段明确列出的类继承关系绘制的静态审核图；不是 V2 要求的运行时可视化。
- `data/ontology/validate.py`：标准 RDF 解析与结构约束校验。
