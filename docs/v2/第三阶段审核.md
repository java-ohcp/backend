# V2 第三阶段：本体规则推理服务（待用户审核）

本阶段依赖第二阶段的本体查询服务，分支为 `feat/v2-ontology-reasoning`。只在本地实现，不推送仓库。新增规则及形态映射仍是待审核候选，不伪造人工审核日志。

## 这次可以验收什么

新增 `POST /api/v1/ontology/analyze`。它读取 TTL、外置规则与 SPARQL，构建一次独立的植株观察，再由 Jena 执行推理。旧 `/diagnose` 和 `/chat` 不调用该接口，原业务尚未切换。

| 能力 | 实现与可核对结果 |
| --- | --- |
| 支持候选 | 部位、形态匹配本体症状，规则推出 `candidate`，不是 Java 直接指定元素 |
| 移动性优先 | 老叶先出现且候选元素属于 MobileMacroNutrient 时，由外置规则标记 prioritized |
| 排除候选 | 观察到老叶均匀黄化、且未观察到脉间失绿时，排除以老叶脉间失绿为特征的候选 |
| 观察冲突 | 同一次观察同时断言老叶最先、新叶最先时返回 CONFLICT，所有候选置为 WITHHELD |
| 分类冲突 | 元素经继承推理进入互斥分类时返回 CONFLICT |
| 新症状归类 | 新建观察仅断言部位与形态，规则自动推得 Discoloration/Necrosis，再沿层级归入 Symptom |
| 过程依据 | 返回实际 SPARQL、结果表、规则文件原文、命中前提三元组、新结论及各三元组是否为显式断言 |
| 删除验证 | 删除排除规则、匹配规则或优先规则后，同一输入的结果分别改变；每次请求重新读取资产 |

## 请求例子

候选与排除：

```json
{"crop":"Rice","observations":[{"part":"OldLeaf","pattern":"UniformChlorosis","first":true}]}
```

预期：`CANDIDATES`；缺氮 `SUPPORTED` 且 prioritized，缺镁 `EXCLUDED`，其他候选 `UNSUPPORTED`。`UNSUPPORTED` 表示没有支持规则，不是已排除。

冲突：

```json
{"crop":"Rice","observations":[{"part":"OldLeaf","pattern":"UniformChlorosis","first":true},{"part":"YoungLeaf","pattern":"InterveinalChlorosis","first":true}]}
```

预期：`CONFLICT`，提示核对首次发生顺序，所有候选为 `WITHHELD`。把第二项 first 改为 false 后不视为先后顺序冲突。不同植株须分别请求，不能合在一次观察中。

未知作物：将 crop 改为 `UnknownCrop`，返回 `NOT_COVERED`，不进入候选推理。

## 资产与运行

- `data/ontology/ohcp-ontology.ttl`：第一阶段通用知识。
- `data/ontology/reasoning-schema.ttl`：本阶段新增观察模型、形态映射、规则解释及互斥约束。
- `data/ontology/ohcp.rules`：7 条可读、外置的 Jena 规则。
- `data/ontology/queries/reasoning-candidates.rq`：从 TTL 读取本次要评估的候选集合，不在 Java 写死候选列表。
- `OntologyReasoningService`：每个请求独立模型，无全局可变观察状态，不写回用户事实。

在 backend 目录启动；可通过 `--agent.ontology.dir=绝对路径` 指定资产根目录。需要重新打包才能让已有运行进程使用新 Java 代码。

接口校验请求体格式、1–10 条观察及受控实体标识。资产缺失或规则不可解析返回 503，不装作正常的“没有匹配”；输入错误返回 400。

本阶段已在本地重新打包并启动到 18080。可打开 `http://127.0.0.1:18080/swagger-ui.html`，在 ontology-controller 的 analyze 接口点击 Try it out 并粘贴上述请求。

## 测试

`mvn test` 覆盖实际 Jena 执行、三种规则删除、首次发生冲突与非冲突对照、互斥类别冲突、自动归类、未知实体、请求隔离，以及真实 Controller 的请求校验与资产错误响应。测试是合成验收，不代表农艺有效性评估。

本次完整回归：74 项，0 失败、0 错误。实际 HTTP 验证：普通观察返回 CANDIDATES、首次发生矛盾返回 CONFLICT、原 SPARQL 查询返回 1 条结果、前端健康代理返回 200。

## 明确边界

- 这里只做本体规则服务，不声称已完成五段式自然语言问答或双过程前端可视化。
- 当前 crop 用于覆盖检查；未审核的 affectsCrop 关系不会被虚构。因此一律 `GENERIC_ONLY`，不返回“该作物已确诊”。
- prioritized 是解释性优先标记，不是概率；没有标定数据，不虚构诊断置信度。
- 排除规则中的 noValue 仅表示本次观察没有输入对应形态，不能解释为现实世界一定不存在它。输入混合症状时不会据此排除。
- 一致性检测覆盖本阶段明确建模的约束，不是完整 OWL DL 一致性证明。
- 规则输出的是候选，不生成施肥用量；施肥建议仍沿用 V1 的证据约束链路。
- 未知情况当前不返回“最接近候选”，以免把未验证相似性包装成知识；该需求待五段式问答阶段补齐。
