# 技术选型 V1.0

> 项目：农作物缺素症识别与科学施肥建议智能体（OHCP 限时编程赛）  
> 定稿日期：2026-10-21  
> 适用范围：后端 + 爬虫（前端另行约定，契约见《前后端对接架构设计》）

---

## 一、决策总表

| #  | 决策项    | 结论                                                | 一句话理由                           |
| -- | ------ | ------------------------------------------------- | ------------------------------- |
| 1  | 爬虫技术栈  | Python（requests + BeautifulSoup）                  | 写清洗逻辑快一倍；离线作业不参与一键启动，多运行时零影响    |
| 2  | 智能体框架  | langchain4j                                       | RAG 组件齐全、Spring 集成好、内置内存向量库     |
| 3  | 大模型    | DeepSeek（deepseek-chat）                           | 中文农学语料好、成本极低、OpenAI 兼容、国内直连稳定   |
| 4  | 向量化    | 通义 text-embedding-v3                              | 质量优；仅构建期调用，向量落盘后运行期不再联网         |
| 5  | 向量存储   | 内存向量索引（langchain4j InMemoryEmbeddingStore）        | 零部署；启动加载 JSONL，规模够用             |
| 6  | 检索策略   | 三路混合（规则矩阵 + BM25 + 向量）RRF 融合                      | 置信度可解释、可复现，直接对应赛题"核心逻辑依赖本地知识库"  |
| 7  | 创新点    | 可解释诊断与反幻觉（置信度四因子 + 证据溯源 + 事实校验）                   | 架构型亮点，几乎不额外耗时，答辩能讲方法论           |
| 8  | 思政落地   | 三路轻量（人物故事 + 价值引导 + 绿色理念）                          | 模板库驱动，成本极低，模型挂了也能输出             |
| 9  | 测试策略   | 轻量验证为主，核心算法补单测（时间够再写）                             | 课堂分享重演示、不重覆盖率，测试只用来兜住"改坏了自己不知道" |
| 10 | 运行时与构建 | JDK 17 + Maven 3.9 + Spring Boot 3.3.x            | 赛题基线，生态最稳                       |
| 11 | 运行方式   | IDE 直接 Run / `mvn spring-boot:run`，极端情况打一个 jar 兜底 | 不要 Docker：不是生产环境，课堂演示怎么快怎么来     |
| 12 | 会话与缓存  | 内存 Map（TTL）+ Caffeine 结果缓存                        | 单机演示不需要 Redis                   |

## 二、明确不引入的技术

| 技术                         | 不引入原因                                 |
| -------------------------- | ------------------------------------- |
| Redis                      | 单机会话用内存 Map 足够，多一个进程多一个失败点            |
| MySQL / PostgreSQL         | 演示数据量下无收益，增加初始化成本                     |
| Elasticsearch              | 千级文档用内存倒排即可，ES 启动慢、吃内存                |
| Qdrant / Milvus / pgvector | 需容器编排，与"无需复杂环境配置"直接冲突                 |
| Kafka 等消息队列                | 无异步解耦需求                               |
| 微服务 / 注册中心                 | 一个进程能解决的事不拆成五个                        |
| Docker / docker-compose    | 不是生产环境，课堂演示直接 IDE 里 Run 最快；容器化只会多一层排障 |
| CI/CD、压测、覆盖率门禁             | 课堂分享用不上，投入产出不成立                       |
| agentscope-java            | 价值在多智能体辩论，本项目单智能体 + 强检索，能力错配          |
| 全自主 ReAct 智能体              | 路径不可预测、时延不可控，现场演示风险高                  |

## 三、依赖清单

### 3.1 后端 pom 关键依赖

版本以 Maven Central 实际可用为准，构建前先跑一次 `mvn -q dependency:tree` 确认无冲突。Spring AI 与 langchain4j 必须通过 BOM / 显式版本锁定。

| 依赖                                    | 用途                          | 备注              |
| ------------------------------------- | --------------------------- | --------------- |
| `spring-boot-starter-web`             | REST + SSE                  | 主干              |
| `spring-boot-starter-validation`      | 参数校验                        | JSR-303         |
| `spring-boot-starter-actuator`        | 健康自检                        | 演示前必用           |
| `spring-ai-starter-model-openai`      | ChatClient / EmbeddingModel | 指向 OpenAI 兼容端点  |
| `langchain4j-core`                    | 向量存储与检索算法                   | 只引核心            |
| `langchain4j-embeddings-...`（可选）      | 内存向量库实现                     | 若单独引内存 store 模块 |
| `caffeine`                            | 结果缓存                        | 重复查询秒回          |
| `springdoc-openapi-starter-webmvc-ui` | 接口文档                        | 答辩可展示           |
| `lombok`                              | 减少样板代码                      | 可选，团队不熟就别引      |
| `spring-boot-starter-test`            | JUnit5 + MockMvc            | 测试              |

**关键：显式排除 langchain4j 的 Spring Boot Starter。** 两套框架都自带模型客户端，同时启用会导致 Bean 冲突、配置重复、日志割裂。约定为——Spring AI 管模型，langchain4j 只管向量存储与检索。

### 3.2 爬虫依赖

```
requests
beautifulsoup4
lxml
```

## 四、关键配置

### 4.1 模型与向量化

| 配置项                                         | 值                          | 说明                      |
| ------------------------------------------- | -------------------------- | ----------------------- |
| `spring.ai.openai.base-url`                 | `https://api.deepseek.com` | DeepSeek 兼容端点           |
| `spring.ai.openai.chat.options.model`       | `deepseek-chat`            | 主力对话模型                  |

| embedding base-url                          | 阿里百炼 OpenAI 兼容端点           | 仅构建期使用                  |
| embedding model                             | `text-embedding-v3`        | 维度 1024（可降 768/512 省内存） |

| `agent.confidence.confirm-threshold` | 0.65                                              |

## 五、代码结构

```
OHCP/
├─ backend/                    Spring Boot（唯一对外服务）
│  ├─ pom.xml
│  └─ src/main/java/com/ohcp/cropagent/
│     ├─ api/                  Controller、DTO、统一响应、异常、SSE
│     ├─ agent/                Orchestrator + 五阶段
│     ├─ retrieval/            RuleMatcher、Bm25Index、VectorIndex、RrfFuser
│     ├─ knowledge/            Repository、Loader、Watcher
│     ├─ llm/                  ChatPort、OpenAiCompatibleAdapter、NullAdapter
│     ├─ guardrail/            ConfidenceScorer、FactValidator
│     ├─ sizheng/              SizhengService
│     ├─ analytics/            QueryLogger
│     └─ config/
├─ crawler/                    Python 离线作业
│  ├─ seeds.txt
│  ├─ crawl.py                 抓取
│  ├─ clean.py                 清洗 + SimHash 去重
│  ├─ structure.py             结构化候选 → 人工审核后合并 deficiency_kb.jsonl
│  ├─ embed.py                 向量化 → vectors.jsonl
│  └─ out/                     中间产物
├─ data/                       三者唯一交汇点
│  ├─ kb/deficiency_kb.jsonl
│  ├─ kb/symptom_rules.json
│  ├─ kb/sizheng.json
│  └─ vectors/vectors.jsonl
├─ frontend/                   前端（另行约定）
└─ docs/
```

三条耦合规则：爬虫只写 `data/`，不调后端；后端只读 `data/`，不调爬虫；后端启动不依赖爬虫是否跑过。

## 六、测试清单（可选，能省则省）

课堂分享以"能演示通"为准，测试不是必做项。如果还有余力，按下面的优先级补，先补前两个就够：

| 优先级        | 测试类                    | 断言什么                                 | 为什么值得写                   |
| ---------- | ---------------------- | ------------------------------------ | ------------------------ |
| 必写（如果只写一个） | `ConfidenceScorerTest` | 缺氮典型输入 > 0.8；缺铁被部位先验抬高；缺氮 vs 缺硫排序不反转 | 置信度是整个方案的核心卖点，算错了答辩会当场露馅 |
| 推荐         | `DegradeTest`          | 模拟模型超时，接口仍返回 200 且降级级别为 1            | 证明"模型挂了也能演示"，这是最硬的一句话    |
| 有余力        | `DiagnoseContractTest` | 成功 / 追问 / 空态三种响应字段结构                 | 防止改了 DTO 忘了同步            |
| 有余力        | `RrfFuserTest`         | 三路融合顺序符合预期                           | 逻辑最简单，写起来 5 分钟           |

不写：E2E、性能压测、集成测试、覆盖率门禁。

## 七、实施顺序（45 分钟版）

| 顺序 | 任务                                 | 耗时     |
| -- | ---------------------------------- | ------ |
| 1  | `pom.xml` + 应用能起来 + `/health` 通    | 8 min  |
| 2  | 爬虫跑通一条链，产出 20~30 条知识 + 规则矩阵 + 思政模板 | 15 min |
| 3  | 规则匹配 → 置信度 → 候选输出（先不接模型）           | 12 min |
| 4  | 六段式装配 + 事实校验 + 思政注入                | 8 min  |
| 5  | 把三个演示样例跑通（缺氮 / 缺铁 / 信息不足），能稳定复现    | 5 min  |

第 3 步结束时就已经能演示"输入症状 → 输出缺素结论"，这是最重要的里程碑。模型接不通也照样出结果。

## 八、风险与兜底

| 风险                     | 兜底                                          |
| ---------------------- | ------------------------------------------- |
| 现场无网 / DeepSeek 不可达    | 切 `offline` profile，走纯模板输出，思政与六段式照常         |
| 阿里百炼密钥没批下来             | 向量通道关闭，降级 BM25 + 规则，识别仍可用                   |
| 两套 AI 框架 Bean 冲突       | 排除 langchain4j 自动装配，模型通道只留 Spring AI        |
| 知识条目太少导致误判             | 优先覆盖 N/P/K/Mg/Fe/Zn/Ca/B 八种高频元素             |
| 爬虫被站点拦截                | 用仓库内已提交的 `data/` 产物，演示时改本地离线采样              |
| 现场机器缺 Maven 或 IDE 环境异常 | 赛前打一个 fat jar 放仓库，`java -jar` 直接起，不依赖 Maven |
