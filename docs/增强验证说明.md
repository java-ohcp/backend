# 智能体与知识生产增强

## 诊断行为

原有接口路径与 DTO 保持兼容。候选必须有已发布知识、可用来源和适用作物，
仅靠规则表存在某个元素不足以产生诊断。只有向量相似度、没有症状规则命中的候选
保守限制在低分段，不能直接确认。前两名分差低于 `agent.confidence.min-margin`
（默认 0.08）、或新老叶信息冲突时先追问，不返回施肥方案。

负面描述如“没有发黄”“未见焦边”不会算作阳性症状；同词第一次是否定、后续肯定时
继续扫描。叶龄否定只作用于当前分句，不将“老叶发黄，新叶正常”中的正常状态扩散。
候选排序使用原始分数，四舍五入只用于显示。评分为启发式匹配值，不是确诊概率。

知识加载保留同一元素的多个审核来源；新增采集证据不覆盖原有完整方案。
加载失败保留上一完整快照。BM25 重建使用新索引快照，不累积旧文档与词频。
方案按请求作物选择已收录条目；未形成结论不提前调用模板或模型润色。

## 独立智能体对接

`POST /api/v1/knowledge/search` 接收：

```json
{"crop":"水稻","query":"下部老叶均匀黄化，植株矮小，分蘖减少","topK":8}
```

返回统一 API 响应，其中 data.matches 包含 id、nutrient、crops、text、sourceUrl、score。
topK 范围 1–20。接口只检索证据，不生成施肥建议；更新后的 `java-ohcp/Agent`
HTTP 适配器可直接使用此地址，也继续兼容此前裸 matches 响应。

## 验证

- 后端 Java 回归覆盖确认、模糊候选、部位冲突、无证据、否定症状、排序精度、
  知识重载、多来源、BM25 重建和检索 HTTP 契约。
- 爬虫离线测试覆盖条件抓取、robots 拒绝、限速/重试、站内边界与页数限制、
  正文大小、段落归属、审核、增量合并及向量失败不损坏旧索引。
- 实测公开文章抓取→清洗→8 条待审候选，重复抓取为 unchanged。
- 真实本地 Spring Boot 服务：标准水稻症状返回 N 候选，信息不足时 advice=null。
- 独立 Java 智能体经真实 HTTP 检索返回 READY / 氮，模型环节使用确定性测试适配器。

测试没有调用真实大模型或付费向量服务，不代表诊断准确率或田间效果评测。
知识库既有人工条目的部分来源仍为站点首页；新增采集审核强制使用精确文章地址，
历史条目的来源完善仍需逐条核对，未在本次伪造替换。
